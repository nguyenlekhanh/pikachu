# Zappy — AI live co-host

Zappy can now answer real TikTok LIVE chat using the **active AI provider** from
Admin → AI Providers. Every conversational line is generated by that provider at runtime:
there is no canned dialogue list, no random canned picker and no simulated response.

The game, TikFinity, gifts, music, leaderboard and animations are unchanged. Zappy is a
conversational co-host only — it cannot change scores, the board, gifts or settings.

## Flow

```
TikFinity chat ──> ingest() ──> engine.handleChat()      (game commands, unchanged)
                        └────> AICohost.observeChat()   (never awaited)
                                   │  filter + score + batch window
                                   ▼
                             active AI provider (aiService.chat)
                                   │  decides + generates one JSON reply
                                   ▼
                        hub.broadcast('mascot', { ai:true, text, emotion })
                                   ▼
                     Zappy bubble + existing English TTS + music duck
```

- The AI call is asynchronous and never blocks TikFinity ingestion, game moves or ticks.
- `aiService.chat()` resolves the active provider on **every** request, so switching from
  OpenRouter to Ollama in Admin takes effect immediately. Nothing in the mascot hardcodes a
  provider or model.

## Setting it up

1. Open **Admin → AI Providers**, verify the provider is CONNECTED and press **SET ACTIVE**.
   On first startup the imported OpenRouter provider is activated automatically when no provider
   was chosen yet; an existing admin choice is never overridden.
2. Open **Admin → AI Mascot** and press **TEST AI RESPONSE**. This sends a real request to the
   active provider and shows the actual generated line, provider, model and latency.
3. Keep chat/game/gift toggles on, set **Conversation frequency**, **Response cooldown**,
   **Max response length** and **AI temperature**, then **SAVE**. Settings are stored in the
   existing settings row and survive restarts.

`RESET GAME & SESSION` clears all conversation memory (messages, replies, topics, per-viewer
timestamps) for the new LIVE session; settings are preserved.

## What reaches the AI

Only a minimal, structured snapshot:

- game status, level, remaining tiles, total matches, auto-play flag
- top 3 leaderboard players and total player count
- last match (player, tile labels, points, combo) and last gift (name, coins)
- current viewer count, if TikFinity reports it
- recent filtered chat and recent Zappy replies (rolling window)

Never included: the board grid, player IDs, admin settings, API keys, tokens, file paths,
logs or private server data.

## Conversation selection

Zappy does not answer every message:

- Coordinates (`A1 B1`) and game commands (`TOP`, `ME`, `HINT`, `JOIN`, `RANK`, `HELP`) are
  ignored — they belong to the game engine.
- Duplicate text within 90 s and more than three messages per viewer per 15 s are dropped.
- Messages are scored for direct address (`Zappy`), questions, game/leaderboard topics, gifts,
  compliments and length, then collected in a **short batching window** (0.8 s high, 1.4 s normal,
  2.4 s low frequency).
- Up to three candidates are sent together, and the AI is explicitly instructed to return an
  empty reply when the message is spam, low value or not worth answering. The AI decides.

Controls that bound cost:

| Control | Behaviour |
|---|---|
| Response cooldown | Minimum seconds between spoken lines (3–180, default 8). |
| Frequency | Low/Normal/High changes batch window, event probability and quiet-chat threshold. |
| Max response length | Hard character cap applied before speech. |
| Temperature | Passed to the provider. |
| One in-flight request | A second opportunity is queued (at most one) or dropped; requests never run in parallel. |
| Retry policy | One retry only for timeout/network/HTTP 5xx; invalid key/model is not retried. |
| Context window | Last 4 chat turns, 8 recent replies and a capped context object. |
| Event commentary | Separate longer cooldown and probability; optional toggle. |
| Random conversation | Off by default; only after a long quiet period when enabled. |

If speech is already active, the browser TTS cancels the previous utterance before speaking, so
two lines are never heard simultaneously. AI lines bypass the TTS cooldown but still replace the
current utterance. Music ducking uses the existing `voice.speak → music.duckFor` path.

## Personality

The persistent system prompt lives in `server/ai/personality.js`: cute, funny, energetic,
friendly, slightly mischievous, casual American English, short one-or-two-sentence replies,
no customer-support tone, no repeated greetings, no emoji/markdown/URLs (they are spoken aloud).

The model returns JSON:

```json
{"reply":"...","emotion":"happy|laughing|surprised|excited|sad|thinking|confused|neutral","reason":"..."}
```

`thinking` maps to the existing sleepy face, `confused` to surprised and `talking` to happy — no new
animation assets. The reply is sanitized (markup, URLs, emoji removed, length capped) before it is
shown or spoken.

## Safety and live chat

- Viewer messages are untrusted data, clearly labeled inside the prompt; the system prompt
  forbids following instructions found in them, revealing prompts/keys/admin data, or claiming
  admin/game powers.
- The server ignores any action the AI might suggest: the only side effect is a `mascot` broadcast.
  Points, leaderboards, gifts, game state and configuration remain engine/admin-only.
- Responses are sanitized and capped; family-friendly rules are in the prompt.
- Errors are redacted and stored in `aiCohost.lastError` for Admin → AI Mascot. On failure Zappy
  says nothing (no fallback line, no provider switch) and the game continues.

## API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/admin/ai` | co-host status: provider, settings, counters, last response/error |
| POST | `/api/admin/ai/test` | real request through the active provider, returns the generated line |

`GET /api/admin/overview` includes the same status under `aiCohost`. All require `x-admin-token`.

## Files

```
server/ai/cohost.js       filtering, batching, memory, cooldowns, AI orchestration
server/ai/personality.js  persistent system prompt, payload builder, reply parsing/sanitizing
server/index.js           hooks chat/game events, broadcasts mascot lines, initial activation
server/api/routes.js      admin status + real test endpoint
client/admin/             AI Mascot section (settings + TEST AI RESPONSE)
client/game/js/mascot.js  existing expressions + intent aliases
client/game/js/voice.js   AI lines bypass the TTS cooldown
```

## Tests

`tests/aiCohost.test.js` covers a real greeting call, game/leaderboard grounding, command and
spam filtering, duplicate suppression, cooldown, disabled mode, sanitized provider failure with
the game still running, AI-chosen silence, length limits, single in-flight requests, active
provider switching (OpenRouter-style to Ollama-style endpoint), real test-response behaviour,
session-reset memory clearing, setting clamps/persistence, gift reactions and prompt sanitizing.

Run everything with `npm test`.

## Limitations

- Speech uses the browser's Web Speech API. OBS browser sources may ship without voices; open the
  overlay once in Chrome/Edge for reliable audio (see `docs/OBS_SETUP.md`).
- The AI provider must be reachable from the machine running this server. A local Ollama server
  must listen on the LAN (`OLLAMA_HOST=0.0.0.0`) and allow its port through the firewall.
- Random unsolicited conversation is off by default to control cost; enable it deliberately.
